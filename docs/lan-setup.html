Studio network

  • How it fits together
  • Setting up the dev server
  • The admin page
  • Setting up a PC
  • Reviewing together
  • Troubleshooting

On a studio network, a group of Windows PCs review the same media together. They all run the same version of DJV. Notes written on one PC appear on the others as they are typed. One server on the network, the dev server, does two jobs:

  • It runs the sync server, which shares the review markers live (see Sharing markers). It decides which PCs are let in and tells them where the media is.
  • It holds the media on a read-only network share.

Each PC has a client ID, the name the server knows it by. The admin registers that ID on the server's admin page. When DJV starts, it contacts the server and maps the media share to a drive letter. Each PC chooses its own letter, and DJV opens the review media from that drive.

How it fits together

A session's markers name the media relative to the share. The same session therefore finds the same file on every PC, whatever letter each one mapped.

Setting up the dev server

  1. Node.js. Install Node.js 22.13 or newer. The sync server needs nothing else; it keeps its sessions in a SQLite database built into Node.
  2. The media share. Share the folder that holds the review media, for example as media, with read-only access for the reviewers. On Windows, this is under the folder's Properties > Sharing > Advanced Sharing, with Read permission only. The PCs reach it as \\<server address>\media. They connect with their own Windows account, or with credentials saved for the server (see Troubleshooting).
  3. The configuration. Copy server/config.example.json to server/config.json and set:
    • name, shown to the reviewers.
    • storage.unc, the media share, for example \\\\10.0.0.5\\media (backslashes are doubled in JSON, or use //10.0.0.5/media).
    • djvVersion, the version every PC should run. A PC running another version is warned. Leave it empty to not check.
    • requireRegistration set to true, so that only registered PCs are let in.
  4. The admin token. Set an admin token so that the admin page can be used from other machines. Use the ADMIN_TOKEN environment variable, or adminToken in the configuration. Without a token, the admin page only works on the dev server itself.
  5. Start the server on the network address: 
    set HOST=0.0.0.0
set ADMIN_TOKEN=some-long-secret
cd server
npm start
    The log says where the configuration is, and gives the address of the admin page.
  6. The firewall. Allow inbound TCP on the port (8787 by default) for the private network profile. For example, in an administrator prompt: 
    netsh advfirewall firewall add rule name="DJV sync server" dir=in action=allow protocol=TCP localport=8787 profile=private
  7. Keep it running. To start the server with the machine, run it as a service, for example with NSSM: nssm install DJVSync "C:\Program Files\nodejs\node.exe" --disable-warning=ExperimentalWarning C:\djv\server\server.js, with the environment variables set in the service's Environment tab. A Task Scheduler task that runs at startup works too.
The sessions are in server/data/djv-sync.db. To back it up, copy it while the server is stopped, or use sqlite3 djv-sync.db ".backup backup.db" while it runs. See server/README.md for the details and the full API.

The admin page

Open http://<dev server>:8787/admin in a browser. It shows:

  • Waiting for approval: PCs that contacted the server but are not registered, with their client ID, address and DJV version. Give one a name and click Approve to let it in. A PC that was refused keeps trying, so it joins within seconds without anyone touching it.
  • Registered clients: rename a client, remove it, or add one by its client ID before the PC has even asked. The table also shows each client's DJV version, address, when it was last seen, and how many sessions it has open. A version other than the expected one is flagged.
  • Connected now: who is following which session.
  • Sessions: each session with its media, its number of markers, and its number of changes.
  • Server settings: the name, the media share, the expected DJV version, and whether registration is required. They are saved to config.json.

Setting up a PC

Open the Settings tool and the Sync Server section:

SettingMeaning
ServerThe sync server, for example http://10.0.0.5:8787.
TokenThe access token, if the server was started with DJV_SYNC_TOKEN. Usually empty on a studio network, where registration is the lock.
Client IDWho this PC is on the server, by default the computer name. It must be unique per PC, and is letters, digits, ., _ and -. Two DJVs on the same PC may share it.
Media driveThe drive letter the media share is mapped to on this PC, for example S:. Only free letters are offered. Each PC chooses its own.
Media shareThe share the server last named. It is set on the admin page, and kept here so that the drive is mapped even when the server is down.
Media folderWhere the media is when no drive is mapped: on a Mac or Linux PC, for example /Volumes/media, or on a PC that reaches the share some other way.
Contact the server and map the drive at startOn by default.

Click Check. The Server line says whether the server was reached and whether this PC is registered; the Drive line says whether the drive is mapped. A PC that is not registered yet now shows on the admin page, waiting for approval. Once the admin approves it, click Check again.

These settings are kept in DJV's settings file (see Settings). To set up many PCs, set up one and copy its Sync section to the others, changing the client ID. Reset in the Settings tool leaves the server, the client ID and the drive alone.

Review/Check Sync Server and Review/Map Media Drive do the same from the menu, and as commands (Review/SyncTestServer, Review/SyncMapDrive) for automation.

Reviewing together

  1. Start DJV. It contacts the server and maps the drive, in the background.
  2. Open the media from the mapped drive, for example S:\shows\abc\sh010\sh010_v003.mov.
  3. In the Review tool's Sync section, give a session name and click Connect. If the session has no media yet, the file you have open becomes its media.
  4. Everyone else connects to the same session. Those with nothing open get the session's media opened from their own drive, with the markers already written.
  5. Add notes as usual. Every addition, edit and deletion reaches the others within a moment.

Save the review (.djvr) to come back to it: opening it joins the same session again.

Troubleshooting

What DJV saysWhat to do
This PC (…) is not registered on the server.Ask the admin to approve it on the admin page. DJV keeps trying and joins once approved.
Cannot reach http://…Check the server address, that the server is running, and the firewall rule. A cached share is still mapped, so files can be opened.
S: is already mapped to …The letter is used for another share. Choose another letter, or disconnect it in File Explorer (This PC > Disconnect network drive).
S: is used by a disk on this PC.Choose another letter.
Windows was not let in to \\…\media.Give your Windows account read access to the share, or save credentials for the server: cmdkey /add:10.0.0.5 /user:reviewer /pass. DJV never stores a password.
…already connected to the server … under another user name.Windows allows one set of credentials per server. Disconnect the other connection (net use lists them), then click Check.
The studio runs DJV 3.7.5; this PC runs 3.7.4.Install the studio's version. Notes still sync, but every PC should run the same DJV.
The sync session's media "…" cannot be found at "…".The drive is not mapped yet, or the file is outside the share. Check the Drive line in the settings, then use Load in the Sync section.

Everything DJV does on the network is written to the Messages tool, and the server writes its own log.
