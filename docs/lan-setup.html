On a studio network, a group of Windows PCs review the same media together. They all run the same version of DJV. Notes written on one PC appear on the others as they are typed. One server on the network, the dev server, does two jobs:

  • It runs the sync server, in Docker, which shares the review markers live (see Sharing markers). The people who review sign in to it with a user name and a password, and it tells their DJV where the media is.
  • It holds the media on a read-only network share.

The admin adds each reviewer on the server's admin page. A reviewer types their user name and password into DJV once. From then on DJV signs in by itself when it starts, and maps the media share to a drive letter. Each PC chooses its own letter, and DJV opens the review media from that drive.

With the same user name and password, reviewers use the server's review portal in a browser. There they upload videos to the media share, make review sessions of one video or two for the people they choose, and open a session in DJV with its review link.

How it fits together

WhereWhatSet up by
Dev serverThe sync server, a Docker container listening on http://192.168.1.40:8877. That address opens the review portal; /admin opens the admin page.Admin
Dev serverThe media, shared read-only as \\192.168.1.40\media to a Windows account called djv, which has a standard password. The sync server writes the portal's uploads to the same folder, which is mounted into its container.Admin
Dev serverThe server's data folder. It holds djv-sync.db (the sessions and the sign-ins) and config.json (the settings and the users, with their passwords hashed). The admin page edits config.json.Admin
Dev serverThe secrets folder. It holds the password of lldjv, the administrator, and the password of the share's djv account, one per file.Admin

When a reviewer signs in, the server gives their DJV the share and the djv account's password. DJV maps the drive with that account, and Windows keeps the account for the server. The reviewers therefore never need the share's password, and the drive can still be mapped when the sync server is down.

A session's markers name the media relative to the share. The same session therefore finds the same file on every PC, whatever letter each one mapped.

Setting up the dev server

The server comes as a package, djv-sync-server-<version>.zip, built from the DJV source with server\build-package.ps1. It holds the Docker image itself, so the dev server needs neither the source nor the internet. The full steps are in the package's docs\docker-deploy.md. In short, on the dev server:

  1. Docker Desktop. Install it, and in its settings turn on Start Docker Desktop when you sign in to your computer. The server's container restarts with Docker.
  2. The package. Unzip it into a folder of its own, for example C:\djv-sync, and open a PowerShell there.
  3. The passwords. Run .\new-secrets.ps1. It writes a strong password for lldjv into secrets\lldjv_password.txt, and the share's standard password into secrets\share_password.txt. To choose the share password yourself, run .\new-secrets.ps1 -SharePassword '…'. Keep the folder private: it is the only copy.
  4. The media share. In a PowerShell started as an administrator, run .\share-setup.ps1 -Path D:\Media. It makes the djv account with the share password, shares the folder read-only to it as media, and opens the firewall for file sharing and for port 8877. It also sets the folder in the server's .env, so that the portal uploads into it. docs\share-setup.md describes the same steps by hand.
  5. Start the server with .\start.ps1. It loads the image, starts the container, and waits until the server answers.
  6. Sign in to the admin page at http://192.168.1.40:8877/admin, as lldjv. Under Server settings, set the media share to \\192.168.1.40\media and the expected DJV version. Then add the reviewers under Users.

The same package runs on any Windows PC with Docker Desktop. Try it on your own machine first: everything works the same at http://localhost:8877.

.\backup.ps1 saves a copy of the database while the server runs, as the admin page's Download a backup does. To change the lldjv password, put the new one in its file and restart the server with .\stop.ps1 then .\start.ps1. To change the share's password, put the new one in its file, run share-setup.ps1 again, and restart the server. The PCs pick it up the next time they sign in. The server's own reference is server/README.md in the DJV source.

The admin page

Open http://192.168.1.40:8877/admin in a browser and sign in as lldjv. Only that user can use the admin page. It shows:

  • Users: the people who may sign in. To add one, give a user name (letters, digits, ., _ and -), their name, and a password of at least 8 characters, then click Add user. Tell them the user name and password. You can rename a user in place. New password gives a user a new password and signs out their DJVs, which then ask for it. Remove signs the user out and stops them signing in. The table also shows when each user last signed in, from which PC, with which DJV version, and how many sessions they have open. A version other than the expected one is flagged.
  • Connected now: who is following which session, from which PC.
  • Sessions: every session, whoever it is for, with its date, description, videos and people, its number of markers and of changes, and who has it open.
  • Server settings: the name, the media share and its account, and the expected DJV version. They are saved to config.json. The page also says whether the share's password was loaded.
  • Database: Download a backup saves a copy of every session, which opens in any SQLite tool.

The review portal

Open http://192.168.1.40:8877 in a browser and sign in with your DJV user name and password. The portal has three tabs. Its full guide is docs\portal.md in the server's package.

  • Sessions: the sessions you are one of the people of, newest first, with their date, description, videos (A and B), people, and number of notes. People who have a session open in DJV now are shown in green. review opens the session in DJV on this PC. Copy link copies the link to send to someone. Whoever made a session, and lldjv, can Edit or Delete it.
  • New session: a description, a date, the people to invite, and one video, or two to compare. The server names the session, so two sessions never clash. Only the people invited, whoever made it, and lldjv see it.
  • Videos: what the media share holds, and an upload by drag and drop into a folder of your choice. Large files go up in pieces, and carry on after a dropped connection; choosing the same file again after closing the page carries on where it stopped. A file never replaces another of the same name. Only lldjv can delete videos.

A session someone starts in DJV by typing a new name belongs to them alone, until they invite others on the portal. Sessions from before the portal are open to everyone.

Review links

Clicking review starts DJV, or brings the DJV already running to the front. DJV then:

  1. asks whether to save the open review, if it has unsaved changes;
  2. closes it;
  3. joins the session, signing in first if it has to;
  4. opens the session's video. A session of two videos opens as A and B, side by side.

DJV takes a link only for the server in its Sync Server settings, and always joins on the address there. The portal may be opened at another address of the same server, such as its name, or localhost on the server itself: DJV asks that address which server it is, and follows the link only if it is its own. This stops a web page from sending DJV, and the password it keeps, to another server.

A link ends in autoConnect=true, which joins the session at once. With autoConnect=false, DJV only fills the session in, in the Review tool's Sync section, and you click Connect when you are ready.

DJV writes every step of a link in the System Log tool (F12), under djv::app::ReviewLink, and every change of the sync connection under djv::app::Sync. Problems also show in Messages. The same is in the log file, %APPDATA%\DJV\djv.3.log.

The installer registers DJV for review links. A DJV that was only unzipped or built registers itself the first time it starts. Review links in the Sync Server settings says which DJV the links open, and Use this DJV makes it this one. The command Review/SyncOpenLink opens a link for automation.

Setting up a PC

Open the Settings tool and the Sync Server section:

SettingMeaning
ServerThe sync server. It is http://192.168.1.40:8877 by default.
User, PasswordThe user name and password the admin gave you. Click Sign in, or press Enter in the password. Once you are signed in, the password is kept in the Windows Credential Manager, and DJV signs in by itself at every start. Sign out forgets it.
Media driveThe drive letter the media share is mapped to on this PC, for example S:. Only free letters are offered. Each PC chooses its own.
Media shareThe share the server last named. It is set on the admin page, and kept here so that the drive is mapped even when the server is down.
Media folderWhere the media is when no drive is mapped: on a Mac or Linux PC, for example /Volumes/media, or on a PC that reaches the share some other way.
Sign in and map the drive at startOn by default.
Review linksWhich DJV the portal's review links open on this PC. Use this DJV makes it this one, for a copy that was moved, or to choose it over another.

The line under the buttons says who you are signed in as. Check signs in again with the kept password and maps the drive. The Server line names the server, and the Drive line says whether the drive is mapped.

These settings are kept in DJV's settings file (see Settings); the password is not. Reset in the Settings tool leaves the server, the user and the drive alone. Two DJVs on the same PC, or one person on several PCs, may use the same user.

Review/Check Sync Server and Review/Map Media Drive do the same from the menu, and as commands (Review/SyncTestServer, Review/SyncMapDrive) for automation.

Reviewing together

  1. Start DJV. It signs in and maps the drive, in the background.
  2. Open the media from the mapped drive, for example S:\shows\abc\sh010\sh010_v003.mov.
  3. In the Review tool's Sync section, give a session name and click Connect. If the session has no media yet, the file you have open becomes its media.
  4. Everyone else connects to the same session. Those with nothing open get the session's media opened from their own drive, with the markers already written.
  5. Add notes as usual. Every addition, edit and deletion reaches the others within a moment.

Save the review (.djvr) to come back to it: opening it joins the same session again, once DJV has signed in.

Or start from the portal: upload the video, make a session of it for the people reviewing it, and each of them clicks review.

Troubleshooting

What DJV saysWhat to do
Not signed in to the sync server.Sign in in the Sync Server settings. A session that was refused joins as soon as you have signed in.
The user name or the password is not right.Type them again, or ask the admin for a new password. After 10 failures from one PC, the server waits a few minutes before it lets anyone sign in from it again.
No password is kept on this PC; sign in.Type the password once and click Sign in.
Cannot reach http://…Check the server address, that the server is running (docker ps on the dev server), and the firewall rule for port 8877. The share last named is still mapped, so files can be opened.
S: is already mapped to …The letter is used for another share. Choose another letter, or disconnect it in File Explorer (This PC > Disconnect network drive).
S: is used by a disk on this PC.Choose another letter.
Windows was not let in to \\…\media as …The share's account or its password does not match the dev server's. Ask the admin to run share-setup.ps1 again and restart the server.
…already connected to the server … under another user name.Windows allows one account per server at a time. Disconnect the other drives or folders open on the dev server (net use lists them), then click Check.
The studio runs DJV 3.7.5; this PC runs 3.7.4.Install the studio's version. Notes still sync, but every PC should run the same DJV.
The sync session's media "…" cannot be found at "…".The drive is not mapped yet, or the file is outside the share. Check the Drive line in the settings, then use Load in the Sync section.
The session "…" was not opened: … is another sync server than this DJV's, ….The portal is of another server than the one in the Sync Server settings. Open that server's portal, or change the setting.
The session "…" was not opened: …, the server the link names, cannot be reached from this PC.The portal was opened at an address this PC cannot reach, such as localhost on another PC. Open it at the address in the Sync Server settings.
The session "…" is not one you were asked to.You are not one of the session's people. Ask whoever made it to add you on the portal.
The session "…" was deleted on the server, or you are no longer one of its people.Disconnect in the Sync section, and join another session.
Clicking review does nothing.DJV is not registered for review links on this PC. Start DJV once, or click Use this DJV in the Sync Server settings. If DJV starts but does not join, the System Log tool says, step by step, how far the link got.

Everything DJV does on the network is written to the Messages tool, and the server writes its own log (docker compose logs in the server's folder).
